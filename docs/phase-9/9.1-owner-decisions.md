# Phase 9 — Owner Decisions (final, from Po)

P1  Login: match LOWER(login) only; input trimmed; characters A-Z a-z 0-9 . _ - ; length 3–64. employee_id stays the unique HR code and is not used for login.
P2  Password policy: 8 to 72 bytes (UTF-8; longer is rejected, never truncated); at least 1 letter and 1 digit; must not equal login, employee_id or the current password; no expiry, no history.
P3  First Admin bootstrap: V018 seeds a default SYSTEM department. A startup runner creates the first Admin only if no user has the ADMIN role, from environment variables for login, password and every other NOT NULL users column; no-op with a warning (no values logged) if any is unset; must_change_password = true (configurable, false in local profile).
P4  While must_change_password is true, only POST /auth/change-password, POST /auth/logout, POST /auth/refresh and GET /auth/me are allowed. Everything else returns 403 with new error code ERR_PASSWORD_CHANGE_REQUIRED.
P5  Lockout: failed_login_count and locked_until reset on successful login and when an expired lock is found on a new attempt. Attempts during an active lock do not increment the counter or extend the lock. All roles including ADMIN are subject to lockout.
P6  Login failures (wrong code, wrong password, inactive, locked): one generic 401 ERR_UNAUTHORIZED "Invalid credentials". A BCrypt comparison always runs (dummy hash for unknown users) so timing does not reveal account state. The real reason goes only to audit_logs.
P7  Refresh tokens: rotate on every refresh; a revoked token presented again revokes its whole family and audits TOKEN_REUSE_DETECTED (strict, no grace window; the frontend must single-flight refresh calls); multiple concurrent sessions allowed, each login starts a new family.
P8  Refresh token format: the existing JwtService refresh JWT (typ=refresh); only its SHA-256 hash is stored in refresh_tokens.
P9  Logout revokes the presented token's family; optional allSessions=true revokes all of the user's tokens. change-password always revokes all of the user's refresh tokens.
P10 Refresh token transport: JSON body over HTTPS (login, refresh and logout).
P11 Login and refresh response: accessToken, refreshToken, tokenType "Bearer", expiresInSeconds, accessTokenExpiresAt (ISO-8601 UTC), user {id, employeeCode, name, roles, mustChangePassword}.
P12 Audit all of: LOGIN_SUCCESS, LOGIN_FAILURE, LOCKOUT, PASSWORD_CHANGE, TOKEN_REFRESH, LOGOUT, TOKEN_REUSE_DETECTED. Failures, lockout and reuse use recordIndependent. Add LOGOUT and TOKEN_REUSE_DETECTED to AuditAction.
P13 Login rate limit: in-memory per-IP limiter on POST /auth/login, default 30 requests per minute (env AUTH_LOGIN_RATE_LIMIT_PER_MINUTE), 429 with new error code ERR_RATE_LIMITED. Client IP from forwarded headers only in staging and prod (server.forward-headers-strategy=native). Built in part 9.3.
P14 Unchanged from earlier: audit logs non-deletable; PM marks material issued while RM is off (later phase).
