# Part 3.4 — API Standards
## Document 02: Error-Handling Architecture and Domain Error Code Catalogue

---

### 1. Confirmed Rules

#### 1.1 Standard Error Response Payload
All non-2xx HTTP responses generated by the Spring Boot backend must return a standardized JSON error envelope:

```typescript
export interface ApiErrorResponse {
  code: string;               // Domain error code (MODULE_REASON)
  message: string;            // Human-readable summary of the error
  details: ErrorDetail[];     // Granular validation or constraint violation breakdown
  timestamp: string;          // ISO-8601 UTC string (YYYY-MM-DDTHH:mm:ss.SSSZ)
  path: string;               // Request URI that originated the error
  correlationId: string;      // Unique request tracing UUID
}

export interface ErrorDetail {
  field?: string;             // DTO field or parameter name (for validation errors)
  rejectedValue?: unknown;    // Submitted invalid value (sanitized)
  message: string;            // Specific constraint failure reason
  code?: string;              // Specific sub-rule error code
}
```

Example JSON Payload (Validation Failure):
```json
{
  "code": "EXECUTION_VALIDATION_FAILED",
  "message": "Input validation failed for operation measurement submission.",
  "details": [
    {
      "field": "measurements[0].actualValue",
      "rejectedValue": "-12.500",
      "message": "Measurement value must be a positive decimal number."
    }
  ],
  "timestamp": "2026-11-26T04:30:00.000Z",
  "path": "/api/v1/piece-operations/op-1024/actions/submit",
  "correlationId": "c4b1e5a2-3f8d-4e92-b2a1-9876543210ab"
}
```

#### 1.2 HTTP Status Code to Exception Mapping
The application `@RestControllerAdvice` global exception handler translates domain exceptions into standard HTTP status codes:

| HTTP Status | Exception Category | Description & Usage |
|:---:|:---|:---|
| `400 Bad Request` | `MalformedRequestException` | Malformed JSON, unparseable UUID, invalid parameter syntax. |
| `401 Unauthorized` | `AuthenticationException` | Missing, expired, or cryptographically invalid JWT token. |
| `403 Forbidden` | `AccessDeniedException` | User authenticated but lacks required permission code (`MODULE_ACTION`). |
| `404 Not Found` | `EntityNotFoundException` | Resource identifier does not exist in the database. |
| `409 Conflict` | `InvalidStateTransitionException`<br/>`OptimisticLockException` | State machine transition disallowed, concurrent modification conflict, or unique constraint violation. |
| `412 Precondition Failed` | `ReadinessGateViolationException` | Business gate blocked (e.g. RM material not issued, predecessor operation not passed). |
| `422 Unprocessable Entity`| `BusinessValidationException`<br/>`ToleranceValidationException` | Syntactically valid request violates domain logic or dimensional tolerance bands. |
| `500 Internal Error` | `UnhandledSystemException` | Unexpected bug, unhandled runtime exception, or database connectivity failure. |
| `502 Bad Gateway` | `ExternalServiceException` | Upstream external system (e.g. RM V-SMART) returned a 5xx error or connection refused. |
| `504 Gateway Timeout` | `ExternalTimeoutException` | Upstream external integration call exceeded socket/read timeout. |

#### 1.3 Error Code Format Specification
* Error codes must strictly follow the format: `MODULE_REASON` in `UPPER_SNAKE_CASE`.
* Module prefixes correspond directly to system modules: `AUTH`, `ORDER`, `PLANNING`, `EXECUTION`, `QUALITY`, `EXCEPTION`, `DOCUMENT`, `INTEGRATION`, `ADMIN`.

### 3. Proposed Design

#### 3.1 Field-Level Validation Mapping
Spring Jakarta Bean Validation (`@Valid`, `@NotNull`, `@Size`, `@DecimalMin`, `@Pattern`) failures are captured by `@ExceptionHandler(MethodArgumentNotValidException.class)` and mapped cleanly into the `details` array of the standard error envelope:
```json
{
  "code": "EXECUTION_VALIDATION_FAILED",
  "message": "Validation failed for 2 field(s).",
  "details": [
    {
      "field": "heatNumber",
      "rejectedValue": "",
      "message": "Heat number must not be blank."
    },
    {
      "field": "quantity",
      "rejectedValue": 0,
      "message": "Quantity must be greater than zero."
    }
  ],
  "timestamp": "2026-11-26T04:30:00.000Z",
  "path": "/api/v1/sales-contracts/import",
  "correlationId": "c4b1e5a2-3f8d-4e92-b2a1-9876543210ab"
}
```

---

### 4. Technical Assumptions
1. **ASSUMPTION:** Correlation IDs are passed from the client or generated via `OncePerRequestFilter` and populated into SLF4J MDC, ensuring every error response includes a traceable `correlationId`.
2. **ASSUMPTION:** Spring Boot 3.4 `@ControllerAdvice` catches all unchecked exceptions, preventing raw stack traces or internal database schema details from leaking in HTTP responses.
