## 3. Secrets Policy

- **Never committed:** `.env`, real `DATABASE_URL` / `DATABASE_DIRECT_URL` credentials, `JWT_SECRET`, R2 keys, SMTP passwords, or RM/ECR service tokens.
- **How each environment supplies secrets:**
  - `local`: `.env` (gitignored, copied from `.env.example`) or shell environment variables.
  - `dev` / `prod`: Render Environment Groups / secret environment variables.
  - `ci`: GitHub Actions holds **no** production or Neon secrets; `NeonConnectivityTests` skips when `DATABASE_URL` is unset.
- **Rotation note:** Rotate `JWT_SECRET`, Neon DB passwords, R2 keys, and RM/ECR tokens in Render and Neon dashboards on compromise or quarterly schedule.

---

## 4. Startup Validation Rules

- **`local` / `ci`:** App starts without `DATABASE_URL` (until Phase 7 Flyway/JPA is enabled); `NeonConnectivityTests` skips via `Assumptions.assumeTrue(...)` when `DATABASE_URL` is unset or contains placeholders.
- **`dev` / `prod` (Phase 6.2+):** Fail fast on startup if `DATABASE_URL`, `DATABASE_DIRECT_URL`, `JWT_SECRET`, or `CORS_ALLOWED_ORIGINS` are missing or contain placeholder values (`USER:PASSWORD`, `CHANGE_ME`, `placeholder`).

---

## 5. Conflicts Between Existing Docs, `.env.example`, and `application*.yml`

1. **Spring Boot version comment in `.env.example`:** `.env.example` line 8 says `Spring Boot 3.4.x / Java 21`, whereas `backend/pom.xml` uses Spring Boot `4.0.3`.
2. **DB URL format in `.env.example` vs JDBC:** `.env.example` lines 15 & 17 use `postgresql://...`, whereas Spring Boot `DataSource` requires `jdbc:postgresql://...` (currently normalized only inside `NeonConnectivityTests.java`).
3. **Missing variables in `.env.example`:** `.env.example` (lines 1–22) does not yet include `CORS_ALLOWED_ORIGINS`, `JWT_SECRET`, `TZ`, `LOG_LEVEL`, R2, SMTP, or RM/ECR variables.

---

## 6. Decisions Applied (Phase 6.2)

1. **Environments:** `local` and `prod` only (plus `ci` for GitHub Actions).
2. **Database URLs:** `DATABASE_URL` and `DATABASE_DIRECT_URL` use `jdbc:postgresql://...` form; `DB_USER` and `DB_PASSWORD` are separate variables.
3. **JWT Secret:** `JWT_SECRET` is HS256, Base64-encoded, minimum 256 bits (32 bytes).
4. **Timezone:** JVM and DB timezone is `UTC`; display timezone `Asia/Kolkata` is frontend-only.
