## 1. Final Domain Module List (9 Domain Modules + Shared Kernel)

Aligned with `docs/phase-4/Phase-4.7-Module-Reconciliation.md` (Part 3.2 `3.2-01` top-level layout under `com.velan.production.<module>`), updated for **C-1 Option A**, **C-2 Option A**, and **C-3**:

1. **`iam`**: Users, credentials, JWT authentication, 6 roles, RBAC individual overrides (required by `SKILLS.md §1.3` and `docs/phase-2/2.2-domain-data-model/02-entity-catalogue-and-attributes.md §10.4`), departments, and sections — owns `users`, `roles`, `user_roles`, `user_permission_overrides`, `departments`, `sections`, `user_sections`.
2. **`order`**: PO and SC intake (RM sync, manual entry, Excel import), product lines, SC revisions, and archive summaries — owns `purchase_orders`, `sc_headers`, `sc_products`, `sc_revisions`, `import_records`, `sc_archive_summary`. *(Removed `production_targets` per C-2 Option A; added `sc_archive_summary` per 7.1.)*
3. **`engineering`**: Catalog products, parameters, checklists, operations, process templates, frozen per-SC-product template steps/parameters/node statuses, dynamic values, and CAD/drawing R2 metadata — owns `products`, `parameters`, `parameter_options`, `checklists`, `checklist_parameters`, `operations`, `operation_parameters`, `operation_checklists`, `process_templates`, `process_template_steps`, `sc_product_template_steps`, `sc_product_node_statuses`, `sc_product_step_parameters`, `sc_product_dynamic_values`, `drawing_documents`. *(Removed `bom_lines`, `tolerance_revisions`, `tolerance_rules`, `process_template_snapshots` per 7.1.)*
4. **`execution`**: Physical pieces, serials, operation routing, operator worklists, operator values, stations/machines, and automatic `Packed`/`Delivered` status derivation from piece state (C-1 Option A) — owns `pieces`, `piece_operations`, `machines`, `operator_values`.
5. **`quality`**: Independent blind QC inspections and measurement values — owns `measurement_values`, `qc_inspections`. *(Replaced `operation_measurements` with `operator_values` in `execution`.)*
6. **`qcexception`** *(renamed from `exception` to avoid confusion with `java.lang.Exception`)*: QC quarantine holds, 4 PM dispositions (`CONTINUE`, `EXTRA_PROCESS`, `RETURN`, `REJECT_AND_RESTART`), and replacement lineage — owns `qc_exceptions`, `pm_dispositions`, `piece_replacement_lineage`.
7. **`vendor`**: External vendor master, RM Delivery Challan (DC) status tracking (no expected-return or actual-return dates; tracks received/partial/not-received status only per `SKILLS.md §1.10`), and inward piece tagging — owns `vendors`, `vendor_dc_trackers`.
8. **`notification`**: Domain event listeners, in-app user notifications, and SSE push stream — owns `user_notifications`. *(Moved `audit_logs` to `shared/audit`.)*
9. **`integration`**: Read-only RM REST connector (`integration.rm`), ECR outbox dispatcher (`integration.ecr`), anti-corruption layer (mapping `sc_headers`/`sc_products`/`sc_number` to RM/ECR names), and sync history — owns `outbox_events`, `rm_sync_history`.

**Dropped for First Release:**
- **`completion` / `dispatch`** (`assembled_sets`, `set_component_allocations`, `packing_records`, `dispatch_confirmations`): Removed per **C-1 Option A** (`D-10` automatic `Packed`/`Delivered`, no packing/dispatch in first release) and **C-2 Option A** (direct RM quantity, no set-assembly model).

**Shared Kernel (not a domain module):**
- **`shared`** (`com.velan.production.shared`): Cross-cutting kernel (`audit`, `config`, `error`, `id`, `time`, `security`, `idempotency`, `scheduling`) — owns `audit_logs`, `files`, `shedlock`, `idempotency_keys`. Has **no `api/` or `internal/` split**.

*(Note: `reporting` is not a separate module; dashboards, KPIs, forecasts, and the daily 9 AM report use cross-module read views.)*

## 2. Backend Package Root & Per-Module Layout

- **Package Root:** `com.velan.production`
- **Per-Module Layout (9 domain modules):**
  - `com.velan.production.<module>.api` — public module facade interfaces, DTOs, and domain events exposed to other modules
  - `com.velan.production.<module>.internal.domain` — entities, value objects, enums, domain services, and repository interfaces
  - `com.velan.production.<module>.internal.application` — use-case services, command/query handlers, transaction boundaries
  - `com.velan.production.<module>.internal.infrastructure` — JPA/Spring Data adapters, REST controllers, schedulers, external clients
- **Shared Kernel:** `com.velan.production.shared` (flat/utility structure, **no `api/` or `internal/` split**)

---

## 3. Layer & Module Dependency Rules

- **Intra-module dependencies:**
  - `api` may depend only on `shared` (and standard JDK/Spring annotations). `api` must **not** depend on `internal.*`.
  - `application` may depend on `domain`, `api`, and `shared`. `application` must **not** depend on `infrastructure`.
  - `domain` may depend only on `shared` and JPA/validation annotations (no Spring Web, no `application`, no `infrastructure`).
  - `infrastructure` may depend on `application`, `domain`, `api`, and `shared`.
- **Cross-module dependencies:**
  - **No cross-module `internal` imports:** No module may import `com.velan.production.<other>.internal.*` (enforced via ArchUnit in Phase 5/6).
  - Modules communicate **only** through `<other>.api` (public facades and published domain events) and `shared`.

---

## 4. O-MOD-02 Decision (JPA Annotations on Domain Entities)

- **Approved:** JPA annotations are allowed directly on domain entities inside `<module>.internal.domain` (single-model approach; no separate `*JpaEntity` persistence layer).
- **Mandatory safety rules:**
  - `spring.jpa.open-in-view=false`
  - `FetchType.LAZY` on all associations
  - `@Version` for optimistic locking
  - No Lombok `@Data`, `@EqualsAndHashCode`, or `@ToString` on entities
  - No public `setStatus(...)` setters (state transitions go through explicit aggregate methods)
  - ArchUnit test in Phase 5 or 6 enforcing that no module can import another module's `internal.domain`

## 5. Naming Rules (`SC` Identifiers & API Path)

- **Database & Code:** Use `sc_number`, `sc_headers`, and `sc_products` in code and DB. Do **not** expand `"SC"` in any identifier.
- **API Path:** Use `/api/v1/scs` (avoid `/sales-contracts`).
