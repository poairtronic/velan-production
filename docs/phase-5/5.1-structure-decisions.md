## 1. Final Module List

Aligned with `docs/phase-4/Phase-4.7-Module-Reconciliation.md` (Part 3.2 `3.2-01` top-level module layout under `com.velan.production.<module>`, with `common` named `shared` per Phase 5.1):

1. **`iam`**: Users, credentials, JWT authentication, 6 roles, RBAC overrides, and departments — owns `users`, `roles`, `user_roles`, `user_permission_overrides`, `departments`.
2. **`order`**: PO and SC intake (RM sync, manual entry, Excel import), product lines, SC revisions, and production targets — owns `purchase_orders`, `sc_headers`, `sc_products`, `sc_revisions`, `import_records`, `production_targets`.
3. **`engineering`**: Catalog products, BOM lines, process templates & snapshots, tolerance revisions/rules, and CAD/drawing R2 metadata — owns `products`, `bom_lines`, `process_templates`, `process_template_steps`, `process_template_snapshots`, `tolerance_revisions`, `tolerance_rules`, `drawing_documents`.
4. **`execution`**: Physical pieces, serials, operation routing, operator worklists, bulk measurement capture, and stations/machines — owns `pieces`, `piece_operations`, `machines`.
5. **`quality`**: Independent blind QC inspections, measurement recording, calibrated gauge checks, and pass/fail verdicts — owns `operation_measurements`, `measurement_values`, `qc_inspections`.
6. **`exception`**: QC quarantine holds, 4 PM dispositions (`CONTINUE`, `EXTRA_PROCESS`, `RETURN`, `REJECT_AND_RESTART`), and replacement lineage — owns `qc_exceptions`, `pm_dispositions`, `piece_replacement_lineage`.
7. **`vendor`**: External vendor master, RM Delivery Challan (DC) status tracking, and inward piece tagging — owns `vendors`, `vendor_dc_trackers`.
8. **`completion`** *(also referred to as `dispatch` in Phase 2 `2.1-02`; scope subject to **Open Conflict C-1**)*: Set completeness, Final QC, physical packing records, and loading dock dispatch confirmations — owns `assembled_sets`, `set_component_allocations`, `packing_records`, `dispatch_confirmations`.
9. **`notification`**: Immutable audit logs, domain event listeners, in-app user notifications, and SSE push stream — owns `audit_logs`, `user_notifications`.
10. **`integration`**: Read-only RM REST connector (`integration.rm`), ECR outbox dispatcher (`integration.ecr`), anti-corruption layer, and sync history — owns `outbox_events`, `rm_sync_history`.
11. **`shared`** *(named `common` in `3.2-01`)*: Cross-cutting kernel (`VelanException`, `ErrorCode`, `Clock`, `ApiResponse`, `PageResponse`), ShedLock, and idempotency support — owns `shedlock`, `idempotency_keys`.

*(Note: `reporting` is not a separate module; dashboards, KPIs, forecasts, and the daily 9 AM report use cross-module read views / `order` and `execution`.)*

## 2. Backend Package Root & Per-Module Layout

- **Package Root:** `com.velan.production`
- **Per-Module Layout:**
  - `com.velan.production.<module>.api` — public module facade interfaces, DTOs, and domain events exposed to other modules
  - `com.velan.production.<module>.internal.domain` — entities, value objects, enums, domain services, and repository interfaces
  - `com.velan.production.<module>.internal.application` — use-case services, command/query handlers, transaction boundaries
  - `com.velan.production.<module>.internal.infrastructure` — JPA/Spring Data adapters, REST controllers, schedulers, external clients
- **Shared Kernel:** `com.velan.production.shared`

---

## 3. Layer & Module Dependency Rules

- **Intra-module dependencies:**
  - `api` may depend only on `shared` (and standard JDK/Spring annotations). `api` must **not** depend on `internal.*`.
  - `application` may depend on `domain`, `api`, and `shared`. `application` must **not** depend on `infrastructure`.
  - `domain` may depend only on `shared` and JPA/validation annotations (no Spring Web, no `application`, no `infrastructure`).
  - `infrastructure` may depend on `application`, `domain`, `api`, and `shared`.
- **Cross-module dependencies:**
  - **No cross-module `internal` imports:** No module may import `com.velan.production.<other>.internal.*` (enforced via ArchUnit in Phase 5/6).
  - Modules communicate **only** through `<other>.api` (public facades and published domain events) and `shared`.

---

## 4. O-MOD-02 Decision (JPA Annotations on Domain Entities)

- **Approved:** JPA annotations are allowed directly on domain entities inside `<module>.internal.domain` (single-model approach; no separate `*JpaEntity` persistence layer).
- **Mandatory safety rules:**
  - `spring.jpa.open-in-view=false`
  - `FetchType.LAZY` on all associations
  - `@Version` for optimistic locking
  - No Lombok `@Data`, `@EqualsAndHashCode`, or `@ToString` on entities
  - No public `setStatus(...)` setters (state transitions go through explicit aggregate methods)
  - ArchUnit test in Phase 5 or 6 enforcing that no module can import another module's `internal.domain`

---

## 5. Naming Rules (`SC` Identifiers & API Path)

- **Database & Code:** Use `sc_number`, `sc_headers`, and `sc_products` in code and DB. Do **not** expand `"SC"` in any identifier.
- **API Path:** Use `/api/v1/scs` (avoid `/sales-contracts`).
