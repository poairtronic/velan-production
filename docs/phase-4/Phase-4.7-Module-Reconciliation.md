## 3. Summary of Structural Mismatches Across Sources

1. **Package Root & ArchUnit Conflict:** `3.2-01` places modules directly at `com.velan.production.<module>` (and `ARCH-01` / `ARCH-05` / `ARCH-12` match `..production.(*)..`), whereas Phase 4 Master Report §9 (and `3.8-01 §2.5` line 98 `..modules.execution..`) uses `com.velan.production.modules.<module>` + `shared` + `infrastructure`.
2. **Module Count Discrepancy:** `2.1-02` defines **10** modules (while `PROJECT_CONTEXT §6` says 11 by adding `reporting`); `3.2-01` defines **11** (`common` added, `dispatch`->`completion`, `audit`->`notification`, still no `reporting`); Phase 4 §9 defines **7 business modules + 2 technical packages = 9** (`modules.orders`, `planning`, `execution`, `quality`, `documents`, `admin`, `integration`, `shared`, `infrastructure`), dropping `iam`, `engineering`, `exception`, `vendor`, `completion`/`dispatch`, `notification`, and `reporting`.
3. **Cross-Part Drift Inside Phase 3:** Even within Phase 3, `3.1-01` cites `security`, `reporting`, and `infrastructure`; `3.4-05` uses `AUTH`, `ORDER`, `PLANNING`, `EXECUTION`, `QUALITY`, `EXCEPTION`, `DOCUMENT`, `NOTIFICATION`, `INTEGRATION`, `ADMIN`, `DISPATCH`; `3.6-01` uses `auth`, `orders`, `planning`, `execution`, `quality`, `exceptions`, `documents`, `notifications`, `admin`.
4. **Internal Phase 2 Table Ownership Drift:** `2.1-02` vs `2.2-02` disagree on `outbox_events` (`exception` vs `integration`), `packing_lists`/`dispatch_clearances` vs `packing_records`/`dispatch_confirmations`, `sub_products`/`bom_items`/`component_set_definitions` vs `bom_lines`, `vendor_operations` vs `vendors`, and `inspection_attachments`.

## 4. Recommendation (Non-Binding — Owner Decision Required)

* **Recommended Structural Baseline:** **Adopt the Part 3.2 top-level module layout (`com.velan.production.<module>` with `api/` and `internal/`)** as the primary architectural root rather than inventing a new 7-module `modules.*` split in Phase 4 §9, because `3.2-01` already specifies the full DAG (`§2.4`), exported facades, and 14 ArchUnit rules (`ARCH-01`–`ARCH-14`), and preserves explicit homes for `exception`, `vendor`, and `iam` without collapsing unrelated domains.
* **Recommended Refinements for Owner Approval:**
  1. Keep `common` (or split `common` + `infrastructure` only if Spring configuration/security filters/S3/Mail adapters need a dedicated non-domain package).
  2. Decide `completion`/`dispatch` strictly via **Conflict C-1** (if `D-10` wins, automatic completion can live in `order`/`execution` with zero `dispatch` module; if Phase 2.6 wins, keep `completion` or `dispatch`).
  3. Decide whether `reporting` (dashboards, 9 AM Excel report, forecasts) is a separate module (`reporting`) or read-only query/scheduler services inside `order` and `execution`.
  4. Align `3.8-01 §2.5` (`..modules.execution..`), `3.4-05`, and `3.6-01` naming once the final backend module list is approved.
