## 1. Authentication & Session Policy

**Q1.1 Login Identifier**  
What should employees use to log in?  
- **Why it matters:** Determines the unique lookup column and login DTO/validation.  
- **Options:** (a) Employee Code / Username, (b) Email, (c) Either Employee Code or Email.  
- **Recommendation:** (a) Employee Code / Username (shop-floor operators may not all have corporate email).

**Q1.2 Credential Type**  
Should all users authenticate with a password, or should shop-floor operators use a PIN?  
- **Why it matters:** Affects hashing policy, complexity rules, and login UI.  
- **Options:** (a) Password for all roles (BCrypt), (b) Password for office roles + PIN for Operators.  
- **Recommendation:** (a) Password for all roles (BCrypt) for uniform security.  
- **Po decision:** 

**Q1.3 JWT Access Token Lifetime & Refresh**  
What should the access token lifetime be, and should we issue refresh tokens?  
- **Why it matters:** Balances shop-floor convenience (8-hour shifts) with security.  
- **Options:** (a) 8h access token, no refresh token, (b) 15–30m access token + 7d refresh token, (c) 1h access token + 12h refresh token.  
- **Recommendation:** (c) 1h access token + 12h refresh token.  
- **Po decision:** 

**Q1.4 Account Lockout & Forced Password Change**  
Should accounts lock after repeated failed logins, and should new/reset users be forced to change their password on first login?  
- **Why it matters:** Required for security hardening in `8.5`.  
- **Options:** (a) Lock for 15 min after 5 failed attempts + force password change on first login, (b) No lockout, only rate limiting.  
- **Recommendation:** (a) Lock for 15 min after 5 failed attempts + force password change on first login.

## 2. Permissions & Section Scope

**Q2.1 Combining Role Permissions, Overrides, and Section Scope**  
`SKILLS.md` states: Admin individual override first, then role grants; explicit deny wins; no grant means deny. How should `user_sections` (section scope) interact with this?  
- **Why it matters:** Operators/QC may be scoped to specific sections, while Admin/PM/Management see all sections.  
- **Options:** (a) Section scope applies to `OPERATOR` and `QC` only (all other roles see all sections), (b) Section scope applies to any user who has rows in `user_sections` (empty = all sections).  
- **Recommendation:** (b) Empty `user_sections` = all sections; if rows exist, filter data to those sections.
