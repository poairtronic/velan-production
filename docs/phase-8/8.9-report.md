## 1. Integration Ports (`com.velan.production.integration.api`)

Every port returns `IntegrationResult<T>` (`AVAILABLE`, `DISABLED`, or `FAILED` with safe message) so callers can never mistake "integration off" for "no data" or "not issued".

| Port | Direction | Data In | Data Out |
|---|---|---|---|
| `SizeCardIntakeSource` | Pull (RM → Production) | `Instant since` | `IntegrationResult<List<SizeCardIntakeNotice>>` (`poNumber`, `sizeCardNo`, `items[productName, quantity]`) |
| `MaterialIssueGate` | Pull (RM → Production) | `isIssued(sizeCardNo, productName)`, `isReplacementMaterialIssued(productionRef)` | `IntegrationResult<Boolean>` |
| `VendorReturnSource` | Pull (RM → Production) | `Instant since` | `IntegrationResult<List<VendorReturnNotice>>` (`dcNumber`, `sizeCardNo`, `productName`, `vendorName`, `processName`, `dispatchedQuantity`, `receivedQuantity`, `status: VendorDcStatus`) — **no date fields** |
| `EcrGateway` | Push (Production → ECR, outbox worker only) | `EcrExceptionPayload` (`productionRef` required `UUID`, `sizeCardNo`, `productName`, `pieceSerial`, `operation`, `exceptionType`, `dispositionType`, `reason`) | `IntegrationResult<EcrAck>` (`ecrReference`) |

## 3. Outbox Column Map & Event Types (`V012` + `V016` + `V017`)

- **`outbox_events` columns:** `id` (`UUID PK`), `aggregate_type` (`VARCHAR(64)`), `aggregate_id` (`VARCHAR(128)`), `event_type` (`VARCHAR(64)`), `payload` (`JSONB`), `status` (`VARCHAR(16)` — `chk_outbox_events_status`), `attempts` (`INT >= 0`), `next_retry_at` (`TIMESTAMPTZ`), `created_at` (`TIMESTAMPTZ`), `sent_at` (`TIMESTAMPTZ NULL`), `sc_id` (`UUID NULL`).
- **`rm_sync_history` columns:** `id` (`UUID PK`), `sync_type` (`VARCHAR(64)`), `started_at` (`TIMESTAMPTZ`), `finished_at` (`TIMESTAMPTZ NULL`), `status` (`VARCHAR(16)` — `chk_rm_sync_history_status`), `records_read` (`INT >= 0`), `records_written` (`INT >= 0`), `error_message` (`TEXT NULL`), `sc_id` (`UUID NULL`).
- **`OutboxEventStatus`:** `PENDING`, `IN_FLIGHT`, `PUBLISHED`, `RETRY_SCHEDULED`, `DEAD_LETTER` (verified against DB in `EnumToDatabaseTests`).
- **`OutboxEventType`:** `ECR_EXCEPTION_RAISED`, `STORAGE_DELETE` (matches `V015__create_purge_sc_function.sql`).
- **`OutboxService.enqueue`:** Runs with `Propagation.REQUIRED` inside the caller's transaction (rollback removes the row), redacts sensitive keys via `AuditRedactor` using `AuditProperties.redactKeys()`, and inserts with `status = PENDING`.

## 4. Disabled-Mode Behaviour Per Port

| Port | Behaviour While Integration Is Off (`DISABLED`) |
|---|---|
| `SizeCardIntakeSource` | Returns `IntegrationResult.disabled()`. Size Card intake operates via **manual entry and Excel import only**. |
| `MaterialIssueGate` | Returns `IntegrationResult.disabled()` (never returns `issued = true`). Material gate cannot be auto-opened by RM; requires a business rule from Po (see §6). |
| `VendorReturnSource` | Returns `IntegrationResult.disabled()`. No automatic vendor DC return polling occurs from RM. |
| `EcrGateway` | Returns `IntegrationResult.disabled()`. Outbox rows remain `PENDING` in `outbox_events` without network calls. |

## 6. Questions & V018 Notes for Po

1. **Question for Po:** *While RM is off, how does the material gate open (for example manual issue by a named role)?*
2. **V018 Note — Outbox deduplication:** `outbox_events` (V012) has no `idempotency_key` or `dedupe_key` column. If database-level deduplication is needed for the Phase 14 outbox relay, add an `idempotency_key` column or unique partial index in V018.
3. **V018 Note — `outbox_events.event_type`:** Currently `VARCHAR(64) NOT NULL` with no `CHECK` constraint; add `chk_outbox_events_event_type` in V018 if strict DB-level enum enforcement is desired.
4. **Schema Note — `customer_name`:** `purchase_orders` and `sc_headers` (V005) have no `customer_name` column, so `SizeCardIntakeNotice` omits `customerName`.
