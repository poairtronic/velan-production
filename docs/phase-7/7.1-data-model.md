## 2. Column-Level Specifications

### 2.1 `parameters` (`engineering`)
| Column | Type | Null | Meaning |
|---|---|---|---|
| `id` | `UUID` | NOT NULL | Primary key |
| `code` | `VARCHAR(64)` | NOT NULL | Unique parameter code |
| `name` | `VARCHAR(150)` | NOT NULL | Display name |
| `kind` | `VARCHAR(16)` | NOT NULL | `STATIC` or `DYNAMIC` |
| `data_type` | `VARCHAR(16)` | NOT NULL | `NUMERIC`, `YES_NO`, `SINGLE_SELECT`, `TEXT`, `SIGNATURE`, `IMAGE` |
| `unit` | `VARCHAR(32)` | NULL | Optional unit |
| `expected_numeric` | `NUMERIC(14,4)` | NULL | Fixed target for `STATIC` + `NUMERIC` |
| `expected_bool` | `BOOLEAN` | NULL | Optional expected answer for `YES_NO` |
| `expected_option_id` | `UUID` | NULL | Optional expected `parameter_options.id` |
| `created_at` / `updated_at` | `TIMESTAMPTZ` | NOT NULL | UTC timestamps |

### 2.2 `sc_product_template_steps` & `sc_product_node_statuses` (`engineering`)
Split frozen structure from mutable node status:
- **`sc_product_template_steps`** (frozen structure): `id` (`UUID`), `sc_id` (`UUID` FK `sc_headers`), `sc_product_id` (`UUID` FK `sc_products`), `source_template_id` (`UUID` NULL), `step_order` (`INT`), `node_type` (`DESIGN`, `RM`, `OPERATION`, `QC`), `operation_id` (`UUID` NULL), `is_extra_process` (`BOOLEAN NOT NULL DEFAULT false`).
- **`sc_product_node_statuses`** (mutable per-product `DESIGN`/`RM`/`QC` status): `id` (`UUID`), `sc_id` (`UUID` FK `sc_headers`), `sc_product_id` (`UUID` FK `sc_products`), `snapshot_step_id` (`UUID` FK `sc_product_template_steps`), `node_status` (`VARCHAR(24)`), `updated_by` (`UUID`), `updated_at` (`TIMESTAMPTZ`).

### 2.3 `sc_product_step_parameters` (`engineering`)
Frozen per-step parameter snapshot so master edits never affect SCs in progress:
| Column | Type | Null | Meaning |
|---|---|---|---|
| `id` | `UUID` | NOT NULL | Primary key |
| `sc_id` | `UUID` | NOT NULL | FK to `sc_headers(id)` |
| `sc_product_id` | `UUID` | NOT NULL | FK to `sc_products(id)` |
| `snapshot_step_id` | `UUID` | NOT NULL | FK to `sc_product_template_steps(id)` |
| `source_parameter_id` | `UUID` | NULL | FK to `parameters(id)` |
| `code` / `name` | `VARCHAR` | NOT NULL | Frozen code & name |
| `kind` / `data_type` | `VARCHAR(16)` | NOT NULL | Frozen `STATIC`/`DYNAMIC` & type |
| `unit` | `VARCHAR(32)` | NULL | Frozen unit |
| `options_json` | `JSONB` | NULL | Frozen `SINGLE_SELECT` options |
| `expected_numeric` / `expected_bool` / `expected_option_code` | typed | NULL | Frozen static expected value |
| `param_order` | `INT` | NOT NULL | Frozen display order |

### 2.4 `sc_product_dynamic_values` (`engineering`)
Keyed on `snapshot_step_id` (not master `operation_id`):
| Column | Type | Null | Meaning |
|---|---|---|---|
| `id` | `UUID` | NOT NULL | Primary key |
| `sc_id` | `UUID` | NOT NULL | FK to `sc_headers(id)` |
| `sc_product_id` | `UUID` | NOT NULL | FK to `sc_products(id)` |
| `snapshot_step_id` | `UUID` | NOT NULL | FK to `sc_product_template_steps(id)` |
| `step_parameter_id` | `UUID` | NOT NULL | FK to `sc_product_step_parameters(id)` |
| `min_value` / `max_value` | `NUMERIC(14,4)` | NULL | Optional limits (target-only allowed) |
| `target_value` | `NUMERIC(14,4)` | NOT NULL | Target numeric value |
| `updated_by` / `updated_at` | `UUID` / `TIMESTAMPTZ` | NOT NULL | Designer audit |

### 2.5 `pieces` (`execution`)
Uses **time-ordered UUIDv7** PKs:
`id` (`UUID` v7), `sc_id` (`UUID` FK `sc_headers`), `sc_product_id` (`UUID` FK `sc_products`), `serial_number` (`VARCHAR(64)` UNIQUE), `status` (`VARCHAR(24)`), `is_replacement` (`BOOLEAN`), `version` (`BIGINT`).

### 2.6 `piece_operations` (`execution`)
Uses **time-ordered UUIDv7** PKs. `snapshot_step_id` is `NOT NULL` (extra-process steps are inserted as `sc_product_template_steps` with `is_extra_process = true`, keeping every `piece_operations` row linked to a snapshot step). Includes `attempt_no INT NOT NULL DEFAULT 1` for rework / return-to-earlier-operation:
`id` (`UUID` v7), `sc_id` (`UUID` FK `sc_headers`), `piece_id` (`UUID` FK `pieces`), `snapshot_step_id` (`UUID NOT NULL` FK `sc_product_template_steps`), `attempt_no` (`INT NOT NULL DEFAULT 1`), `machine_id` (`UUID` NULL), `status` (`VARCHAR(24)`), `version` (`BIGINT`).

### 2.7 `operator_values` (`execution`)
Uses **time-ordered UUIDv7** PKs. Keyed on `snapshot_step_id` + `step_parameter_id`. Stored statuses are `DRAFT` and `SUBMITTED` only (double-check is a UI confirm screen):
`id` (`UUID` v7), `sc_id` (`UUID`), `piece_id` (`UUID`), `piece_operation_id` (`UUID`), `snapshot_step_id` (`UUID`), `step_parameter_id` (`UUID`), `status` (`DRAFT` | `SUBMITTED`), `val_numeric`, `val_bool`, `val_text`, `val_option_id`, `val_file_id`, `judged_min`, `judged_max`, `judged_target`, `result` (`PASS` | `FAIL` | `NA`), `submitted_by`, `submitted_at`.

### 2.8 `files` (`shared`)
`id` (`UUID`), `sc_id` (`UUID` NULL — `NULL` for archive-pack files so they survive purge; set for SC-owned signatures/images/drawings), `storage_key` (`VARCHAR(512)` UNIQUE), `file_name`, `content_type`, `size_bytes`, `checksum_sha256`, `uploaded_by`, `uploaded_at`.

### 2.9 `sc_archive_summary` (`order`)
`id` (`UUID`), `sc_id` (`UUID` — no FK, survives purge), `sc_number` (`VARCHAR(64)`), `status` (`EXPORTED` | `APPROVED` | `PURGED`), `excel_file_id` (`UUID` FK `files`), `pdf_file_id` (`UUID` FK `files`), `piece_count` (`INT`), `operation_count` (`INT`), `value_count` (`INT`), `archived_at` (`TIMESTAMPTZ`), `approved_by` (`UUID` NULL), `approved_at` (`TIMESTAMPTZ` NULL), `purged_at` (`TIMESTAMPTZ` NULL).

## 3. Constraints & Immutability

- **Unique Keys:** `piece_operations(piece_id, snapshot_step_id, attempt_no)`, `sc_product_dynamic_values(snapshot_step_id, step_parameter_id)`, `operator_values(piece_operation_id, step_parameter_id)`.
- **Check Constraints:**
  - `sc_products`: `quantity > 0` (150 max is an application setting).
  - `operator_values`:
    - `status IN ('DRAFT', 'SUBMITTED')`
    - `status <> 'SUBMITTED' OR (result IS NOT NULL AND submitted_by IS NOT NULL AND submitted_at IS NOT NULL)`
    - `status <> 'SUBMITTED'` requires **exactly one** typed value column non-null; `DRAFT` allows `<= 1`.
    - `judged_target IS NOT NULL` when `SUBMITTED` and `val_numeric IS NOT NULL`.
    - Type-match between `step_parameter.data_type` and `val_*` enforced in application service + integration test.
- **Submitted Row Lock (Phase 7.5):** PostgreSQL `BEFORE UPDATE OR DELETE` trigger on `operator_values` raising an exception when `OLD.status = 'SUBMITTED'`.

## 4. Purge Path (Per `sc_id`, After User Approval)

- **Exempt:** `audit_logs` (deleted only by Admin, recorded in `audit_logs`), `sc_archive_summary`, archive-pack `files` (`sc_id IS NULL`).
- **SC-owned `files` (`sc_id = :scId`):** deleted from R2 object storage and `files` table.
- **Ordered deletion (`WHERE sc_id = :scId`, children → parents):**
  1. `measurement_values`
  2. `qc_inspections`
  3. `pm_dispositions`
  4. `piece_replacement_lineage`
  5. `qc_exceptions`
  6. `operator_values`
  7. `piece_operations`
  8. `pieces`
  9. `sc_product_dynamic_values`
  10. `sc_product_step_parameters`
  11. `sc_product_node_statuses`
  12. `sc_product_template_steps`
  13. `drawing_documents`
  14. `vendor_dc_trackers`
  15. `sc_revisions`
  16. `import_records`
  17. `sc_products`
  18. `files` (`WHERE sc_id = :scId`)
  19. `sc_headers`

## 5. Volume Estimate, Index Plan & Test Plan

- **Volume:** 100 SCs × 8 products × 150 pieces = 120,000 `pieces`; × 18 ops = 2,160,000 `piece_operations`; × (15 dynamic + ~5 static = 20 params) = 43,200,000 `operator_values` per PO (bounded by per-SC archive & purge).
- **Index Plan:**
  - `sc_headers(po_id)` — PO detail; `sc_products(sc_id)`, `sc_products(product_id)` — SC intake
  - `sc_product_template_steps(sc_product_id, step_order)` — routing freeze; `sc_product_step_parameters(snapshot_step_id)` — step params
  - `sc_product_dynamic_values(snapshot_step_id)` — limit lookup
  - `pieces(sc_id, status)`, `pieces(sc_product_id)` — worklist & auto `Packed`/`Delivered`
  - `piece_operations(piece_id, status)`, `piece_operations(sc_id)` — operator queue & purge
  - `operator_values(piece_operation_id)`, `operator_values(sc_id)` — draft/submit & purge
  - `audit_logs(created_at)`, `audit_logs(entity_type, entity_id)` — Admin audit query
  - `files(sc_id)` — SC file purge; `user_notifications(user_id, is_read, created_at)` — SSE/inbox
  - `outbox_events(status, next_retry_at)` — ECR outbox poller
- **Test Plan:** Include an **`sc_id` consistency test** verifying every SC-owned table's `sc_id` matches its parent `sc_headers.id` and that purge leaves zero rows for `:scId`.
